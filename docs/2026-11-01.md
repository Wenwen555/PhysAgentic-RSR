## M2.0：Always-Slow 与效率

先固定整个 case 的开发／测试划分：按 friction × 已知 grip command 分层，
NumPy RNG seed 20261101，每层 2 个开发 CoM、3 个测试 CoM，共 8/12 cases。
在开发 case 选择一个固定慢速候选 P7/P8，得到 **P8**。
测试 case 的 GT seeds 1001–1032 按索引拆为 16 个 Oracle 选择种子及 16 个独立评估种子。
Sim 选择固定为 M1 的独立 seeds 1–8 结果，不能再看测试 GT 改选。

| 方法 | 留出测试成功率 | 相对独立 Oracle 的估计 regret |
|---|---:|---:|
| Direct-CaP | 0.7604 | 0.0729 |
| Always-Slow P8 | 0.8333 | 0 |
| Sim-CaP | 0.8177 | 0.0156 |
| 独立种子 Oracle | 0.8333 | 0 |

Sim − Always-Slow = **−0.0156**，case bootstrap 95% CI **[−0.0469, 0]**。
Oracle headroom 相对 Always-Slow 为 0；不能从这一数据宣称仿真选择提高成功率。
独立 Oracle 是 noisy reference，并非逐样本绝对上界，regret 允许负值。

限制：这是 retrospective holdout，之前已看过 M1 整体结果；物理值仍来自同一网格。
**P8 的 `where=com` 在 M1 使用真实 CoM**，所以这里是同等 oracle 信息下的慢速基线，
并非未知物体无需辨识即可执行的基线。后续 Motion 使用显式数值偏移，禁止执行时查询 CoM。
初次按 case 名称奇偶分割混淆 grip 条件的旧报告已删除；有效分层划分及其结果保留。

### 执行时间补测

M1 的 `duration_s` 是并行运行的主机墙钟时间，不能当作机器人执行时间。
新增 `sim_duration_s` 从 reset 后 MuJoCo 时间计起，覆盖接近、夹持、抬升及 hold。
20 cases × 8 programs × seeds 2001/2002 = **320** 条独立补测，未重新挑选程序。

- 全 20 cases：Sim **14.6688 s**，P8 **14.7675 s**；差 **−0.0988 s**，
  case bootstrap CI **[−0.3325, +0.1363]**。
- 留出 12 cases：差 **−0.2938 s**，CI **[−0.5583, −0.0979]**。
- 留出集中两者样本成功率均 ≥0.95 的 9 cases：差 **−0.2111 s**，
  CI **[−0.3389, −0.0833]**。

全体和留出集口径同时报告：存在约 1–2% 的小幅留出集时间收益，但未出现强而普遍的效率优势。
不能只报告全体非显著值，也不能只选留出显著值。失败更早结束 hold 会缩短时钟，
所以并列报告两者都达到样本可靠性阈值的子集，仍不是 population reliability 证明。

合并报告逐 case 给出全部程序成功率、主机耗时、独立物理耗时、0.8/0.9/0.95/1.0
阈值下的可行程序与最快程序。0.95 下最快程序分布为 P5:4、P1:2、P2:2、P7:1、P8:1，
另 2 cases 无可行候选，说明物理条件影响经验可行集；不证明最优程序估计稳定。
每格仅 16 个独立评估 seeds，即使 16/16，单侧 exact 95% lower bound 约 0.829。
**没有 case/program 获得 ≥0.95 的置信保证**；59/59 才刚达到单项单侧要求，
多候选选择还须独立验证或同时推断。bootstrap 区间按 case 聚类，未声称新的物理总体已覆盖。

## M2.1 原型：固定 Probe → 模型集合更新 → 数值程序验证

冻结配置后运行 4 个连续 World：
`(CoM,mu)=(-.045,1.1),(.045,1.1),(-.075,1.7),(.075,1.7)`，grip command 均为已知 2 N。
质心偏移通过既有隐藏配重实现，质量、惯量随之变化；不能声称独立辨识惯量或恒质量 CoM。

模型库 `CoM∈{-.09,0,.09} × mu∈{.7,2.0}`，初始错误模型 `CoM=0, mu=.7`。
两个固定 Probe：数值偏移 ±.04 m，抬升 .04 m，speed=.35，均使用机器人控制 API。
特征为接触至抬升末端的物体位移、物体相对 TCP 的位移、倾斜绝对量及夹爪宽度。
只读取模拟视觉／本体状态，不读取 hidden MJCF、质量、摩擦或 CoM；没有真实力反馈通道。
误差尺度固定为位移 .01 m、倾斜 .1、宽度 .005 m，均方损失更新离散模型权重。
权重保留多解，但不是经过噪声校准的贝叶斯后验。

完整任务固定数值抓取点 {- .06, 0, +.06} m × {全速,.35}，抬升 .1 m，
不以 World physics 解析 `where=com`。模型 seeds 11/12，World probe seed 101，
最终评估 seeds 1001–1004，动作幅度与接触点均与 Probe 不同。
模型 96 rollouts、World probes 8、World task trials 96，每轮共 **200**。
任务评估数据完全不进入辨识器。模型库 amortized 成本与实际任务试验分开记账。

当前控制是 observation-only 规则而非 LLM Coding Agent：Direct+Probe 按左右 Probe
倾斜和滑移选择同侧慢速抓取；Unupdated、Updated 使用相同模型动作预测和经验 .95
可行性约束（若无可行程序取最高预测成功率）。直接规则尚非充分优化的公平最终基线。

### 结果与诊断

- Direct+Probe、Unupdated、Updated 最终成功率均为 **0**。
- 所有 4 cases 的全部 6 个数值候选均失败，经验候选 Oracle 为 **0/96**。
- Held-out success-rate MAE：初始 **0.3333**，更新 **0.1637**。
  但是恒定预测全部失败可得 **0** MAE，因此这个下降不构成有效预测增益证明。
- 排序因真实候选成功率全部相同而不可定义；不能用分类 accuracy 或零 false-pass
  包装成好模型。更新权重分散，参数不可唯一辨识。
- 更新模型集合的 held-out 位移／滑移 RMSE 约 10.8–18.6 mm，倾斜 MAE 0.166–0.198，
  不能仅凭 Probe 拟合好声称可以预测完整抬升。
- 后续**事后精确 CoM 抓取诊断**使用同 World、同 seeds：慢速 **16/16**；
  全速分别 1/4、1/4、0/4、2/4。它不是加入主比较的新候选，也不替换主实验成绩。
  这说明任务本身可行，现有数值抓取池没有覆盖足够精确的局部接触点；速度仍有条件性作用。

模型库同样缺少局部可行抓取模型：非零 CoM 模型下数值任务动作全部失败，仅零 CoM
模型预测中心抓取成功。平均集合预测后，选择保持中心，不能把物理信息转成可行程序。
Probe 的 4 cm 短抬成功也不能推断 10 cm 任务成功。

### 隔离与实现边界

初次诊断不同角色复用 spawn pool，虽各 rollout env 独立，仍不足以称为强角色隔离。
代码已改为 role-dedicated Model/World Probe/World Task pools，另行同协议重跑。
可信 evaluator 保存真值用于离线评分；辨识和选择函数只接收数值观测与模型库。
这符合固定程序研究的独立执行，但不是防恶意同 UID Python 的安全沙箱；M2.3 任意代码
执行仍需要文件系统／进程权限隔离。没有给任意生成代码开放本 worker。
尚未完成在线预算授权 World RPC、Oracle Simulator 对照、强 Reactive-CaP、迭代修订、
任务 completion error、每步记录、实际力传感器、LLM 成本追踪；不能把这些原型接口标为已交付。

## Claim 状态与下一步

1. **Predictive Simulation Adds Value：未获得支持。** M2.0 未胜过固定慢速成功率；
   小幅时间优势不足以单独支撑强论点。M2.1 候选上界为零，不能进行有效因果归因。
2. **Task-sufficient Identification Is Possible：尚未验证。** 参数支持较宽，held-out
   动态误差仍大，且没有通过辨识产生可行程序。不能据此断言需要恢复全部物理参数。
3. **Active Probing Reduces Adaptation Cost：未检验。** M2.2 未实施；先修复 M2.1 有效性。

下一协议需预先冻结而非就地改分：

- 使用连续抓取点作为有明确物理依据的动作参数，检查抓取精度和实测 CoM 附近的可行区间，
  不通过随机加候选制造 headroom。将精确 CoM 阳性对照保留为 evaluator-only 检查。
- 在独立开发配置上设计带方向的负载响应观测、分段短抬与受控移动；验证观测对接触点、
  CoM 与有效摩擦裕度的敏感性。检测欠拟合与参数混淆，再决定估计物理参数还是任务稳定裕度。
- 先检查内部模型库／优化器在连续抓取点上有足够局部覆盖，再冻结新的物理测试配置与种子。
  当前 4 个配置已经是诊断开发证据，不能再冒充未见测试集。
- 完成 Oracle Simulator、使用相同物理信息的 Direct+Probe 与正常反馈能力的 Reactive-CaP；
  通过 held-out 预测与最终 World 操作的门槛后，才比较四种 Active Probe 目标和预算。
