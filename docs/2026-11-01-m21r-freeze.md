# M2.1-R 低成本失败归因审计与冻结

状态：冻结为 `physrsr-m21r-v1-failure-audit`。本轮只复用已有记录，新增 World rollout=0、
Model rollout=0，不修改原始方法、参数辨识、候选或成绩，不推进 M2.2。

## 代码清理

删除未使用的 import 与临时变量；`Program.specification()` 只复制程序参数，不再深复制随后丢弃的
观测 trace，并继续复制可变 stages，避免返回值修改影响程序。更正 selector 的注释：原规则平局
保留候选顺序，不是“距离优先”。保持历史实验复现入口与所有旧数据，未删除既有控制修复。
新增只读审计 `failure_audit.py`、冻结／校验工具 `freeze.py` 和针对配对、排序平分、预算重放、
参数序列化的回归测试。

## 1. Simulator 是否舍弃成功程序？

80个配对 trial：共同成功19、Direct成功而Sim失败21、Direct失败而Sim成功8、共同失败32。
**40个 Direct 成功 trial 中，21个被改为失败（52.5%）。** 损失集中于 case0、4、6，
救回集中于 case2。净差 -13/80=-.1625，case-bootstrap 95% CI [-.500,.200]，总体差异仍不精确。

关键机制：三个损失 case 的 Direct 与选中程序在内部模型中都预测100%成功。
选择器并未发现 Direct 不可行，而是在模型过宽的“可行集”中按预测耗时改选。
case0、6同时改速度／偏移；case4仅改偏移，不能将失败统一解释成速度过快。

上表物理数值为四舍五入的描述，机器可读精确值见审计 JSON。
舍弃成功的三个 case 都有摩擦高估，且改选后实际抓取误差更大。但假阳性也存在于摩擦低估的
case1、5（Direct与Sim都失败），所以不能把所有模型错误归因于摩擦高估。

按 **估计 CoM 误差>5 mm** 分组，被模型判通过的5个case的选中程序 World trial 失败率72.5%；
≤5 mm组对应33.3%。这是10个case上的事后描述，CoM、摩擦、配重质量／惯量及控制动作混淆，
不构成某个物理参数的独立因果作用证明。负对照case8、9模型本来就预测失败，不是误判通过。

## 3. 候选 GT 排序是否被模型排错？

10个case中，**5个选中程序低于其候选池 GT 最优成功率**（case0、1、4、5、6）。
整个池的经验 Oracle SR=.7875，而Sim选中SR=.3375；池上界是完整样本最大值，存在乐观偏差。
审计另保存独立GT种子半拆 Oracle，避免将完整样本上界当成无偏参考。

对 GT 成功率不同的259个候选对：严格逆序41个（15.8%），模型平分128个（49.4%）。
因此既有真正排序颠倒，也有大面积分数区分能力不足；不能将模型平分称为严格逆序。
例如case6没有严格逆序，但36个GT不同候选对中27个模型平分，依旧会按预测时间选错。
JSON逐case保存全部候选的GT排序、模型排序、平局名次、概率和抓取参数。

## 4. 搜索量与验证量必须区分

固定Direct为每个子集的必选候选，穷举其余组合，不以GT选择子集；保持原候选顺序和原选择规则。
候选数k∈{1,2,4,6,10}，验证种子数n∈{1,2}，模型预算=k×n。
n=1分别重放两个已有模型种子并平均，n=2同时使用它们。完整k=10,n=2的10个选择逐一与主实验一致。

|候选数k|n=1 World SR|n=2 World SR|n=2预测乐观偏差|候选池经验Oracle|
|---:|---:|---:|---:|---:|
|1|.5000|.5000|.2000|.5000|
|2|.3979|.3972|.3472|.5653|
|4|.3231|.3284|.4501|.6624|
|6|.3149|.3294|.4623|.7262|
|10|.3250|.3375|.4625|.7875|

扩大候选池提高Oracle，却降低实际选择表现、扩大预测乐观偏差，支持**固定池内更多搜索暴露／利用
模型误差的迹象**。但曲线并非严格单调；case较少，预算点不是独立新实验，不能声称搜索越多必然越差。

验证种子从1变2的完整池SR略升（.325→.3375），**没有证据说明更多验证会恶化结果**。
现有记录仅有两个模型种子，不能回答n>2的验证预算；本轮不新增仿真，保持审计低成本。
