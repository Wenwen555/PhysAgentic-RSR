# M2.1-S — 共享静态审查、轨迹反馈与修订门控

本轮只改变 Rod Lift 的 Coding Agent 修订协议，不调整辨识器、物理分布以追求收益、控制器或成功标准。
旧 M1/M2/Coding Agent 输出保持不变。实现位于
[m21s](../physrsr/m21s/README.md)，执行仍经原受限机器人 RPC，保留真实机械臂可实现的相同 API。

## 预先固定的协议

每个 case/generation 的初始程序经过**一次共享 LLM 静态审查**，包括语法/API、base 坐标与 CoM 变换、
四元数和调平方向、控制参数、循环退出与重抓/释放状态机。分叉之前源码、物理信息与完整对话前缀相同。
A/B/D 各有一次最后修订调用，使用逐字相同的静态要求；C 复用 B 的候选，不重新生成。

| 方法 | 最后调用的额外执行证据 | 部署判定 |
|---|---|---|
| A Physics-informed | 无 | 共同的确定性静态检查 |
| B Original Sim | 末尾 4 个旧 phase 样本 | 同一静态检查，无物理门控 |
| C Original Sim + Gate | 与 B 完全相同候选 | 静态检查 + 配对 Model 验证 |
| D Structured Sim + Gate | 控制步轨迹里程碑及首次异常连续窗口 | 与 C 相同门控、验证种子和预算 |

B/C 的“原始反馈”保留旧尾部表示，但**坐标错误在所有反馈中统一修复**。否则 C/D 的差别会混合坐标正确性
与过程证据。旧 phase 的原始 world 坐标仍保留，明确标注 raw frame metadata；发送给 Agent 前转换到 base。
D 的物体/TCP 位姿、相对位移均为 base，时间来自仿真时钟。每个底层控制步及 API 前后都有采样，包括 blocking
motion 内部；不仅采样外层 `_step_once`。完整轨迹不截断，提示给出首次异常前后窗口与关键事件。

`feedback.py` 区分 never_grasped、never_lifted、excessive_tilt、grasp_lost、lifted_then_dropped、
target_not_reached、program_error/timeout。允许多标签；末态 not_lifted 不再解释为从未抬起。
原始接触谓词可作为 Model 开发诊断，**没有增加 policy 的运行时 grasp 传感器**。
相对位移包含转动影响，不冒称纯接触滑移。`possible_causes` 默认空，LLM 必须把观测事实、假设和可证明代码错误分开。

静态检查器包含 AST 检查和三个**无物理动力学的运动学合同重放**：正/负倾斜和保持下沉。
重放仍在隔离 guest 中执行，通过数学/状态转移反例检测反向调平和高位释放。
这不是通用 Python 形式化证明，也不是对所有传感情形的穷尽验证；所有组拥有相同检查。

门控只使用 4 个未向 Agent 展示的配对 Model 验证种子。任何 success→failure 或新严重过程事件拒绝替换；
修复至少需要 2 个 failure→success 且单侧 sign p≤.10，实际 4 个种子下需要 4 个一致修复。
成功率无提升时，仅接受四个种子均成功、均快至少 10%、目标误差未恶化超过 3mm 的候选；
或四个种子目标误差均改善至少 5mm 且时间不恶化超过 5%。同样要求 sign p≤.10。
持平或证据不足保留共享基线。此规则是保守选择启发式，**不是 World 可靠性置信保证**。
after-Model 的开发/验证数据只做记录/门控，不进入额外 LLM 调用。

全部规则与后续独立 cohort 已在读取其 World 结果前保存到
[preregistered.json](/data/wjt/PhyAgent-RSR/output/physics_cap_m21s_logs/preregistered.json)。不按显著性追加 seed 或修订轮数。

## Cohort 与成本边界

正式 v3 使用共享静态回滚和绝对高度误差 `abs(.10-rise)`，不改变 legacy task success、门控阈值或修订次数。
两次中止版本及开发 smoke 的输出和对应日志已删除。正式 v3 已完整复制实际复用的 prompt、响应、代码和 Model 轨迹；历史复用来源标记保留，不再依赖被删目录。

已知配置检查完成后、独立 cohort 开始前，将反馈的 lifted 里程碑统一到**原任务的 tabletop-clearance 谓词**，
避免把“相对初始杆中心抬升 4cm”误当成任务的“高于桌面 4cm”；评分条件不变。
同时在控制步记录最近一次请求的 base-frame 位置/四元数/速度，明确它不是底层关节伺服目标。
此改动支持首次异常窗口中的控制证据，不增加 policy 观测权限或 LLM 次数。
独立 cohort 不复用此前提示或生成代码，源码以自身 `source.tar.gz` 为准。
完整回归为 **39 passed**，补入控制命令元数据用例后，最终协议单测 **14 passed**（共 40 个不同用例通过）。

已知配置检查固定复用原 4 cases × 2 generations 的全部初始程序。每分支新增共享审查一次及 A/B/D 三次调用，
新调用总数为 32；历史初始程序各含原来的两次调用，缓存来源单独记录。该 cohort 用于协议有效性检查。

摩擦 Uniform(1.1,2.0)），每配置两次独立初始代码生成。沿用两个固定 Probe 和旧辨识库；
每路径初始/共享审查/最终修订各一次，A/B/D 共享前缀，C 不新增调用；合计应为 40 次新调用。
不重新优化辨识器，也不筛选失败 case。

### 全部冻结 D 候选的事后反事实

为区分“gate 压制了有效代码”和“代码本身没有修复能力”，对**全部八份**冻结 D 候选在**原有四个 World 种子**
上另执行 32 次；不新增 LLM、不新增代码或种子、不选择有利候选、不改主表。
见 [raw_D_report.json](/data/wjt/PhyAgent-RSR/output/physics_cap_m21s_independent/raw_D_report.json)。

* 未门控 D 为 **14/32=.4375，CI [.125,.8125]**；相对基线/A/B 修复 **0**、破坏 **1**。
* Gate-D 相对原始 D 保住 1 次成功，差 +.03125，探索性 cluster CI [0,+.09375]；不是跨任务显著收益。
* 因原始 D 在每个测试配对上都没有 failure→success，任何只在这些候选与基线之间选择的 gate，
  都不可能提高这批 World SR。因此 gate 保守不是本轮零修复的唯一原因。
* gate 确实很保守：4 个验证种子、p≤.10 意味着只有 4 个一致修复才能凭成功率证据接受。
  本轮拒绝了 1/4→4/4 和 2/4→4/4 的候选，不能将拒绝全部称为检测到退化。
  保留这个操作点及负结果，不事后放宽规则。

唯一被破坏的是 **case0/gen0/16001**。原始程序成功，D 候选先抬到约 110.6mm 且保持抓住，
随后在约 105.5mm 的高度反复请求相同目标，若干请求没有推进仿真时间；36 次运输/保持循环耗尽，
在 61.5s 执行 `lower_after_failure()`，62.85s 记录抓取丢失/掉落。
该程序将自身 4mm 名义目标资格检查与新增跟随要求未满足解释为恢复条件，主动降回桌面。
它没有修复输入日志中的首次抓取失败，反而破坏了一条成功路径。
这支持“额外保持/恢复逻辑和底层收敛精度交互”的代码问题，不支持把该例归咎于 CoM 估计（误差仅 .148mm）。
静态合同的完美运动学输入没有覆盖这类控制精度/停滞情形；gate 因收益证据不足保留了基线，
不能声称它提前知道这个 World 失败。

同三种合同输入下，独立 cohort 的 A/B/D 都是 8/8 AST 变化，但实际动作命令变化分别为 **1/8、3/8、5/8**。
更多动作修订没有产生成功修复。该受限行为审计与逐份 rationale/diff 一起保存，未把 AST 变化当成语义改进。

## 研究结论与冻结决定

1. **结构化反馈**能正确表达已抬升后掉落、高位释放及异常邻域，Agent 也会据此改写动作；
   本批候选未产生独立 World 修复，不能宣称它优于原始反馈的任务收益。
2. **Revision Gate**确实能够拒绝配对退化，并在已知 Oracle 和一份新 D 候选上避免破坏；
   它没有使主实验优于强静态基线，且小验证预算下过于保守、增加了成本。不能把全回滚当作可靠适应成功。
3. **完整增强协议 vs Physics-informed**：独立 World SR、修复数与成功样本执行时间均无额外收益。
   本轮未支持“可执行物理仿真增加可靠操作收益”的核心 claim，而不是因为没有实现仿真闭环。

共享已审查基线自身就是 15/32，C/D 在独立集最终完全返回该代码。
一个不再调用 Model 的 Always-Keep-Reviewed 规则即可复制这个 SR；不能把 gate 保住坏修订前的成功，
当成 Simulator 相对该静态基线的独立收益。

四个层次分开解释：辨识器未改动，不主张参数估计提升；反馈表达改善不等于物理预测精度改善；
修订动作变多不等于生成质量提高；已知程序回归修复不等于独立任务成功率提升。
有限的 case 数、点模型与初态覆盖、非物理合同覆盖不足、底层控制精度与程序保持/恢复逻辑交互，都是剩余限制。

本轮冻结，不追加 seed、候选或修订轮数，不推进 M2.2。Rod Lift 保留为辨识→代码生成及 harness 回归基准；
不建议继续在相同协议上堆 Sim 预算。下一轮先限定解决跨任务的 TCP 收敛/保持资格/恢复合同和模型不确定性问题；
若研究重点仍是 Simulator 对复杂接触程序修订的独立价值，可为 Pushing & Reorientation 建立新的预注册任务研究。
当前结果不是已具备可靠泛化链路的证据，本轮没有实现这些新任务。
