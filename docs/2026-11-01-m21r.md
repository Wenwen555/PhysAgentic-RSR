# PhysRSR M2.1-R：Physics-conditioned CaP Synthesis

## 审计结论

Git 根为 `src/cap-x`，base commit `53e9966d7a8e2fa7494676772bccc35280f5c0ed`。
开始时存在既有控制修复、物理环境和前轮实验等未提交修改；本轮不重置、不提交或覆盖它们。

旧 0/96 程序使用物体局部坐标数值偏移 {-0.06,0,+0.06} m；Oracle 阳性对照将同一个
`Motion.offset` 改为真实 CoM，speed=.35，其他控制 API、夹持力、hold 与成功条件相同。
没有给 Oracle 更强底层控制器。`rod_pose` 从观测 wxyz 四元数取得物体正 x 轴，
`centre + axis*offset` 得到机器人基坐标目标。符号及姿态变换一致。
旧辨识器更新集合权重，但没有把估计 CoM 传入程序生成器；因此可行局部抓取点没有进入候选池。

新 Program 完全不读取传入的 PhysicsSpec，而使用生成时冻结的数值 offset。
估计器只接收跟踪位姿与 TCP 响应，GT 只存在可信评估器和 World 专用进程中。
实际 World 和 Model 使用不同角色的 spawn pool，不复用进程；不是防恶意 Python 的 OS 沙箱。

## Task B：抓取误差干预

开发配置使用旧四个诊断 World，另加 CoM=.03、mu=.65、已知 grip=2 N 的负对照。
粗扫描每 case 对 Δx=-4…+4 cm 使用相同 8 个 seeds 3101–3108，固定 speed=.35，
共 360 rollouts。测试控制器按真 CoM+Δx 构造干预；这些真值不进入普通 Agent。

粗扫描四个正常配置仅 Δx=0 时 8/8，其余 ±1–4 cm 全失败。负对照精确抓 CoM 仍失败。
随后开发阶段细化到 Δx={-5,-2.5,0,+2.5,+5} mm，独立 seeds 3301–3308，共 200 rollouts：

| CoM / mu | -5 mm | -2.5 mm | 0 | +2.5 mm | +5 mm |
|---|---:|---:|---:|---:|---:|
| -.045 / 1.1 | 1 | 1 | 1 | 1 | 1 |
| +.045 / 1.1 | 1 | 1 | 1 | 1 | 1 |
| -.075 / 1.7 | .875 | .75 | .75 | 1 | 1 |
| +.075 / 1.7 | 1 | 1 | 1 | 1 | 1 |
| +.03 / .65 | 0 | 0 | 0 | 0 | 0 |

因此开发配置需要毫米级局部定位，5–10 mm 之间边界未细化，不能插值宣称稳定连续区间。
一个配置精确 CoM 在不同初始种子下也会失败；CoM 精度不是唯一可靠性因素。
这些是样本成功率，8/8 的单侧 95% binomial lower bound 仅约 .688，不是成功概率≥.95保证。
不能把这些开发配置的窄容差直接当成所有摩擦／质量条件下的统一必要阈值。

粗扫描记录终端旋转角、相对 TCP 滑移、failure reason 和物理执行时间。
曲线保存在 sensitivity 输出目录；最终合并图包含粗／细两组独立 seeds。
物体质量和惯量随现有配重 CoM 模型一起改变，不能单独归因于恒质量的 CoM 移动。

## Task C：识别与生成接口

`m21r/core.py`：`generate_candidates(task, physics_estimate, uncertainty, control_constraints)`
生成 `x_grasp=xhat+delta`，冻结候选数值、speed、阶段及可重放 Python。
主协议 delta={-10,-5,0,+5,+10} mm、speed∈{.35,None}，每 case 10 个局部候选。
Direct 固定选择估计 CoM 的慢速候选；Sim 在同候选中先满足经验预测 SR≥.95，再最小化
执行时间，无可行程序时取最高预测成功率。两组执行相同候选生成与编译预算。
这是一轮参数化代码模板生成与局部参数修订，不是 LLM 自主合成或复杂多轮 Agent。

静态过滤包含杆端余量、配置的抓取范围与可选外部 workspace predicate；不声称完整 IK／
碰撞证书。所有组走相同机器人 API，仿真／真机接口一致，但硬件 object tracker 与实机测试未完成。

两个固定 Probe 偏移 ±.025 m，speed=.35，分段抬升 .02/.04/.06 m；只记录接触及各段末端
物体 pose 与 TCP。特征包括垂直位移、相对 TCP 滑移、**带符号的物体长轴倾斜**。
相比旧绝对 tilt，方向信息可用；仍不读取真实 CoM、惯量、摩擦或不可用力反馈。

共同辨识器使用正则模型库 CoM=-.09:.01:.09、mu={1,1.5,2}（57 models，114 Probe rollouts），
固定 seed41，按三段响应做规则网格插值和有界 least-squares 反演。前三个 grid loss 起点确定性
优化。保留 loss≤best+1 的模型支持作为非校准不确定范围，而不虚构参数置信区间。
**两种 Identified 方法共享这项 inverse-simulation calibration 成本**；Direct 是没有在线
任务仿真，不是辨识阶段完全没有使用 Simulator。
开发 Probe seed3201 上 CoM 误差约 -15、-5.8、+15、-23.6 mm，不能声称识别已准确。

## 核心结果：参数、预测、生成与执行分别报告

10 个预设 case × 每方法 8 个最终种子，主要结果保留两个负对照：

| 方法 | World SR | case bootstrap 95% CI | 执行时间 s |
|---|---:|---|---:|
| Geometric-CaP | 0 | [0,0] | 14.363 |
| Oracle-CoM-CaP | .7875 | [.500,1.000] | 14.427 |
| Identified-CoM-CaP | .5000 | [.200,.800] | 14.052 |
| Identified-CoM + Sim | .3375 | [.100,.6375] | 14.010 |
| Wrong-CoM（-xhat） | 0 | [0,0] | 14.134 |

- Δ_ID = **+.5000 [.200,.800]**。
- Δ_Sim = **−.1625 [−.500,+.200]**；未支持额外成功率收益，点估计更差。
- Sim − Direct 执行时间 **−.0419 s [−.2863,+.2538]**；没有显著效率收益。
  失败提前停止 hold 也会缩短时钟，所以不能把小的无显著时间差当作有效操作效率提高。

所有区间使用 10000 次 case cluster bootstrap，固定 seed20261101，条件于已采样初始种子。
[0,0] 是全零数据上的退化 bootstrap 结果，**不是总体失败概率为1的置信证明**。
逐 case 另有 binomial lower bounds；没有任何 8-seed cell 获得 SR≥.95 的置信保证。
本实验范围是弱夹持 2 N、偏置 CoM 的指定物体族，不代表默认 20 N 或近中心 CoM 的任务总体。

预设 8 个正常配置另报（不替换主结果）：Geo=0、Oracle=.9844、ID=.625、ID+Sim=.4219。
两个低摩擦负对照四个核心组全部失败，Oracle 也不可行；未删除这些 cases。

### RQ1：多少精度才足够？

开发干预说明 tested weak-grip cases 的可行区域通常在毫米尺度，但精确 CoM 也不必然成功。
测试中 CoM MAE 从先验 52.38 mm 降至 **15.88 mm**；正常配置从 53.99 mm 降至 **8.90 mm**。
仍有两个正常 case 误差约 14–20 mm；低摩擦先验外 case 误差更大。
全体 |CoM error| 与 Identified SR 的 Spearman 为 **−.870**，这只是跨配置关联，受摩擦和负对照影响，
不作为统一精度阈值的因果证据；因果误差干预来自 Task B。

测得接触时实际 TCP 沿物体长轴偏移与命令的差：mean absolute **0.152 mm**、p95 **0.593 mm**、
max **1.020 mm**。这个量远小于主要 CoM 估计误差，未发现坐标传递或抓取位置控制的系统性符号问题。
跟踪假设是有方向的理想物体 pose；真机需要标记／跟踪坐标定义，不能假设无纹理对称杆自动区分正负端。

参数不确定支持仅覆盖 6/10 个真实 CoM（正常 case 6/8），说明目前的 loss-support 不是可靠置信区间。
mu 与 CoM、接触及初始状态的响应存在混淆；calibration 只有一个独立初始种子，不能把插值最优解当成准确辨识。

### RQ2：辨识是否转化为可行 CaP？

**在指定测试域内获得支持。** ID 比固定几何中心的成功率提高 .5；错误 CoM 对照仍为0。
生成程序确实从先验中心移到 xhat，测试与源代码验证了估计值被消费；不再是旧固定池只重排权重。
但 ID=.5 与 Oracle=.7875 仍有明显差距，不等于“所有配置已完成任务充分辨识”。
也没有证明这一模板优于所有可能的固定／符号启发式抓取规则，更没有证明 LLM 自主代码合成。

### RQ3：仿真是否提供额外验证／修订价值？

**当前实现未获得支持。** 模型局部验证救回 case2（ID 0→Sim 1），但使 case0、4（1→0）
及 case6（1→.375）退化。速度／偏移修订的单次成功不能掩盖总体负结果。

同一批生成程序、同样内部 seeds 上，更新前后模型对 held-out World 成功率 MAE：
**.35875 → .25625**，配对变化 **−.1025 [−.285,+.060]**，区间跨零。
更新后 held-out trial-level 预测 accuracy **.73875**，case 内平均排序 Spearman **.238**。
这些预测指标不能替代任务表现；也不能从 MAE 点估计下降宣称显著预测改善。

模型预测通过的候选在 World 中仍有 **38.66% trial 失败**；若按“该程序 World 样本 SR<.95”
计算 cell 级经验 false-pass，比例为 **55.81%**。最终选中并被模型判通过的 8 个 case 中，
5 个未达 World 样本 .95，条件 trial failure 达 **57.81%**。
点模型、先验失配和只有两种子的乐观可行性判断共同造成假阳性；当前不确定性没有参与稳健验证。

独立 GT seed 半拆 Oracle 的平均 selection regret：ID **.275**，ID+Sim **.475**。
这里 Oracle 是生成池内参考，不是 Oracle-CoM 参考组，不能用完整样本 SR 直接相减代替独立估计。

### Task E：0→1→2 个 Probe

冻结的前缀审计中，直接生成程序 World SR 为 **0 → .675 → .500**。
CoM MAE 为 **52.38 → 28.65 → 15.88 mm**（正常子集 **53.99 → 9.32 → 8.90 mm**）。
整体参数 MAE 改善，并没有保证任务 SR 单调改善：第二个 Probe 改善了一些原本已可行 case 的估计，
也把 case1、5 的估计推离可行区，分别损失 .875 的成功率。
这正说明参数精度、预测精度、程序变化及任务收益必须分开评价。
不能看到这个结果后把“只用第一个 Probe”事后升级为主协议最佳方法；新策略仍需要新的独立测试。

## 成本、失败模式与阶段决策

两个共享 Probe 每对象总 World 时间约 **36.7 s**；Probe+一次最终操作平均 **50.78 s**（ID）
和 **50.74 s**（ID+Sim）。Sim 额外需要每对象 **20 次在线任务模型 rollout**，
累计 model host workload 约 **55.36 s/object**，对应内部物理时间 **288.12 s/object**；
host workload 不是并行总 wall time。共同识别库另有 114 次离线 rollout。
20 次先验预测、200 次同程序前后模型审计、前缀审计的20次模型与80次World评分属于 evaluator 成本，
不计作 Agent 得到的额外信息。实验无运行时 LLM 调用，开发对话 token 不在此计费口径。

生成池完整 World 评分 1040 rollouts（10 cases×13 programs×8 seeds）；这不等于部署探索预算。
主实验另有20次World Probe及220次模型预测。粗／细开发扫描560次，校准114次，开发Probe8次，
前缀审计100次，固定程序前后模型审计200次；另4次新程序确定性／接触验证。
所有实验均无 infrastructure error。Runner 已增加 error 写入后立即中止路径及其单测。

失败主要为 lift 中倾斜／抬升失败，而不是坐标转换。
ID 的40个失败 trial 为 not_level14、not_lifted25、not_grasped1；Sim 的53个失败为15、36、2。
低摩擦下准确抓 CoM 仍失败属于能力边界；其余假阳性不能归因于这些负对照，因为负对照未被模型判通过。

本轮满足 RQ2 的基础链路：观测→参数估计→可重放新程序→World 成功。
RQ1 只得到条件性精度／可行区认识，尚未获得稳健的任务充分辨识；RQ3 没有增益证据。
**暂不进入完整 M2.2 Program-aware Active Probe 比较。** 先做以下受控修复再冻结新测试集：

1. 条件化模型预测所需的可观测初始姿态、接触构型与机器人状态，扩大校准初始状态覆盖；
   比较点参数与多合理模型的风险，校准不确定性及 out-of-prior 检测。
2. 对“参数误差变小但任务变差”采用 Task B 的条件性风险分析；不因参数 MAE 下降自动接受更新。
3. 在开发集明确内部可行性判定所需验证量和 false-pass 约束，保持正常 Direct 反馈能力与计算公平；
   不能用2/2宣称95%可靠。修复后用新配置检验仿真修订是否真正增益。

可以据此规划辨识成本研究，但目前没有证据支持 Active Probe 已有效，也没有实施 M2.2/M2.3。

最终测试 **38 passed**（27.14 s，2项既有依赖弃用警告）。完整配置、source-at-run 快照、
生成程序、rollouts、统计、图及最终工作树 provenance 均已保存；旧 M1/M2 文件不变。


最终接口复查：评估日志的 `RolloutRecord.case_id` 编码物理条件。原 `identify` 始终只处理
传感特征，但控制器包装函数曾接收含此元数据的完整记录，入口不够严格。
现增加 `sensor_view` 白名单，仅允许 index、motion、pose/TCP observations 进入 adaptation，
并对含 evaluator 字段的输入直接拒绝。`agent_observations.json` 保存净化后的输入；
全部10个case的估计和生成程序逐一重放，与冻结结果相同（CoM atol=1e-12、程序参数完全一致）。
`boundary_replay.json` 记录验证。没有重新挑程序或改World成绩；source-at-run 与最终源码均保留。

ID 40个失败和 ID+Sim 53个失败的 phase 归因全部为 lift；接近／坐标管线不是主要故障来源。
