# 当前运行与证据合同

主流程保持一个 World、一个预测会话、一份共享任务源码；所有仿真及 World 请求串行。
本合同说明代码执行与证据认证条件，不是实验成功或统计校准报告。

## 配置与首次交互

`read_config` 检查任务目标、成功条件、约束、注册适配器和 16 个基础误差尺度。
外部任务需显式提供 `adapter=MODULE:FACTORY`，且服务端也注册该适配器。
适配器的 `validate_task(task)` 必须无交互、无环境初始化地检查任务合同。
Loop 在 `target.prepare` 前调用 `sim.validate_task`、读取能力和初始观测、检查对象身份及特征版本。
不会静默修复错误的特征维数。对象数量确定后，明确推导场景尺度排列。
启动时的准备成本计入 `spent`；未知准备成本会停止交付。

## 联合拟合与权重

Agent 提出物理参数支持集，宿主对唯一的物理支持赋均匀先验，按所有唯一 fit Evidence ID 重算。
响应中的 Agent weight 不作为已经条件化的先验。重复重放同一数据集不能让后验进一步收缩。
每个存活假设必须通过每段数据的误差阈值；不接受“不同假设各解释不同片段”的拼接。
对象响应和共享机器人通道分别检查，额外静止对象不会稀释一个通道的失配。
失败矩阵和接受的模型 ID 保存在 `models/fit_review_*.json`，并反馈到下一轮物理评估。
修订或交互预算耗尽时才结束相应路径。

`Estimate` 要求有限数值、包含估计值的有序区间、明确单位/坐标系和假设。
新返回估计还必须匹配 Probe 声明的 `estimator_outputs`；场景估计须绑定正确对象 ID。
错误估计进入程序修复反馈，不提交无效记忆。

## 独立干预验证

唯一 `DESIGN_SCHEMA` 的 `validation` 字段在拟合时为 null，在验证时为结构化合同：

- 当前任务候选的 SHA256，以及目标对象和有效物理假设 ID。
- 竞争解释、任务操作和对象坐标系中的接触设置及位置容差。
- 每个设置的接触暴露时间、TCP/对象位移、对象转角、升高和腕部激励下界。
- 不高于宿主限制的预测误差接受标准。

宿主从候选的模拟轨迹推导操作覆盖下界，逐设置核对实际轨迹。
一个设置不能借用另一个设置的暴露时间；多段续执行的设置和观测会一起核对。
接近对象、夹持动作、测得的对象响应和加载时间是可观测覆盖条件，不冒充接触真值传感器。
AST 哈希只检查源码完整性和明显重复（含局部变量重命名）；实际动作指纹也不能代替干预覆盖。
验证通过只对当前模型版本和当前任务候选有效，不能自动迁移到新策略。

预测失配进入持续的 `validation_failures`，同版本另一条通过记录不能清除。
退休失败必须有新的 fit 证据；新模型还须解释这些退休轨迹的矛盾，然后重新采集新的独立验证。
退休验证不参与权重拟合，也不作为新版本的认证数据。
每个设置的对象运动和腕部激励使用该设置开始前的独立基准，不能借用先前设置的位移、载荷或暴露时间。

## 观测与统计范围

`measured_response_v3` 为单对象 16 维。
`measured_scene_response_v2` 为每对象 6 维响应加一次共享腕部的 10 维响应；三对象共 28 维。
均值按物理时间积分；重复时间戳不增加权重。旧投影不得用于新版本似然。
仿真在控制步以约 20 Hz 保存完整观测，包括执行结束后的单杆评分保持段。
硬件若需要瞬态统计，须由可信适配器提供同步、固定采样的 `drain_observations()`，不能用重复 RPC 或主机 sleep 补造轨迹。

特征尺度和似然是工程近似，尚不是传感噪声与跨特征协方差的统计校准。
对象/TCP 相对响应还按一个共有分量和对象间差异处理，避免同一 TCP 跟踪变化在静止对象上被重复计权。
这些相关性处理仍是工程精度近似，不表示全部剩余通道物理独立。
后验权重、有限候选值和模型集合稳健性不得描述为真实成功率的置信区间。

## 探索与预算

`probe_candidates`（1–4，默认 2）控制已有候选范围内的可执行 Probe 比较数量；每份程序顺序预测。
计算收益使用模拟中测得的设置/执行时长，Agent 的 benefit 不覆盖低计算收益。
`new_structure` 和 bootstrap 仅使用独立的 `max_heuristic_probes / max_heuristic_cost` 额度并明确标记。
停止还检查有限候选集的计算遗憾值、未解决矛盾和当前候选的验证覆盖，不声称全局探索最优。

执行服务管理 192 次 RPC 上限、准备及程序实际时间、不同接触设置数，以及新接触前的恢复预留。
`max_distinct_settings` 的可执行定义是分辨率内不同的对象/接触位置；更抽象实验变量的设置由测量合同解释。
`max_local_excitation_*` 是设计约束，不是通用机器人控制器的自动幅度裁剪。
设置和时间估计不是实际成本；测量成本独立归档，超额时保留证据并停止认证。

每次执行记录准备后的 `execution_budget`，包括实际 RPC、控制器时间及接触设置上限。
`TaskAdapter.execute(..., execution_budget=...)` 必须把它应用到模型中的程序执行输入；不支持该合同的适配器在首次交互前拒绝。
拟合回放使用原证据的实际预算，不能重新赋予默认预算而令自适应程序走另一条分支。
验证的实际预算与预先估计不同时，保留原预测，再以该实际控制输入、原记忆及固定模型作确定性对齐预测，
不使用验证观测拟合参数或权重；对齐原因单独归档。这是给定执行输入的独立检验，不能混称为未对齐的原始预测。

控制器时间限制在 RPC 前后、受限 hold 和准备步上执行；宿主/IK 延迟由独立的墙钟截止管理，不改变仿真控制器时间。同步控制器调用的中途取消必须由实际控制服务实现；
宿主不能抢占一个不返回的设备调用。真机集成必须提供控制器级 deadline/取消能力，不能把宿主预算检查当作实时安全控制。

## 冻结与正式执行

`final/` 保存逐字源码、辨识记忆、任务、模型、执行配置和运行清单及各自哈希。
清单绑定不可被 belief 更新改写的 World ID、对象 ID、模型版本和执行器合同。
真实控制器应在更换实物/标定范围时更换 World 身份；不能复用同一 ID 冒充同一物理实例。
默认服务重启会产生新身份，需要重新辨识；不自动将旧估计移植到新服务。

`execute` 在任何策略动作前核对身份、任务、执行器和全部冻结输入的哈希，
仅向匹配的 World 恢复记忆，并再次核对实际执行使用的记忆；返回源码哈希也必须相同。
旧 bundle 没有这些绑定，不能沿用原认证；历史文件不改写。

退出码：0 为执行完成且 `task_result.success is True`；2 为程序或任务失败；3 为执行完成但任务评分不可用。
单杆 `target.execute_policy` 复用正式的物理保持评分，三杆复用整场景抬升/保持/放回评分。
硬件没有真实评分器时只能返回评分不可用，不能依靠程序自报成功。

## 可迁移清单与源码交付

每次运行保存主项目源码/Prompt 快照及 SHA256、Git 提交和差异、CaP-X/必需 Robosuite 版本、
控制器 JSON、Python 与安装依赖版本、Agent 服务 ID/模型/后端和 Prompt 哈希。
请求和响应有内容哈希，生成源码和证据 ID 统一绑定到 `run_manifest.json`。
认证前核对源文件、控制器配置和 Agent 配置未在运行中变更。

主仓库 `tests/active/` 是当前测试集；子模块原测试保留为历史源码，不作为当前 pytest 默认入口。
`dependencies.lock.json` 给出所有子模块的精确提交；`tools/restore_dependencies.py` 支持无 `.git` 的 ZIP 恢复依赖。
`tools/export_source.py` 生成包含自有测试、逐文件 SHA256 及递归依赖 Git 内容清单的 ZIP；
默认提供锁定清单，`--include-capx` 可附带必需依赖源码及资源。环境和模型权重另行安装。
